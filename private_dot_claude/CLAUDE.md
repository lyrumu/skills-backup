# 全局工作约定

## 工具优先原则

任务开始前先扫描可用 skill 与 MCP 工具列表。只要有 1% 可能适用，就先调用它，而不是自己从零实现。

- **文档查询**：任何库 / 框架 / SDK / API / CLI 的用法、配置、版本迁移问题，先用 context7 MCP（`resolve-library-id` → `query-docs`），不要凭记忆作答——训练数据可能已过时。
- **浏览器操作**：页面交互、E2E 验证、截图、检查控制台报错、确认前端改动真的生效，一律用 playwright MCP，不要靠推测。
- **调研与并行**：多文件调研、大范围搜索、彼此独立的子任务，派发 Agent 子代理并行执行；无依赖的工具调用放在同一批发出。
- **专门 skill 必走**：代码审查、代码简化、安全审查、数据可视化、前端设计、写计划、系统化调试、TDD 等任务存在对应 skill，必须调用，不要手写等价流程。

## 不要绕开

- 不要因为「感觉直接做更快」就跳过已安装的 skill / MCP。
- skill 或 MCP 调用失败时，明确报告失败原因，不要静默降级为手写实现。
- 不确定某个能力是否存在时，先用 `find-skills` 查，不要假设没有。

## 工作约定

- **先读懂再改**：修改具体文件前先读代码；需求不明确必须先问我，禁止猜测。
- **第一性原理**：解决问题回到本质；复杂后端逻辑做对抗性审查；时刻注意代码规范性与可维护性。
- **不污染系统环境**：优先局部 / 虚拟环境，不动全局配置。
- **前端优化不动后端**：做 UI 优化时确保后端逻辑不变、功能不减少。
- **终端命令写注释**：每条 terminal 命令说明在做什么。
- **少用真实浏览器**：除非必要，不用真实浏览器。
- **代理访问**：涉及国外网络时用 `/bin/zsh -ic 'proxyon && <实际命令>'`。`proxyon` 定义在 `~/.zshrc`，需交互式 zsh 加载；开代理与实际网络命令必须在同一次 shell 调用中执行，不要假设环境变量跨工具调用保留。
- **用完即关**：本地用于诊断、测试的服务进程使用后及时关闭。
