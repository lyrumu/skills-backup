# 动态排查

发现入口不是删除白名单。以下软件/目录名仅为线索；不存在就跳过，发现新的大项就扩展，不照抄其他设备的路径或清单。

## 定位与覆盖

- 识别当前账户/home、系统版本、挂载卷、实际项目和已安装/运行的软件；解析相关环境变量与应用配置（如 `CODEX_HOME`、XDG 路径）。用 `getconf DARWIN_USER_TEMP_DIR`、`getconf DARWIN_USER_CACHE_DIR` 及当前 `TMPDIR` 定位用户临时区，不硬编码 var/folders 随机段。
- 用 `df -k` 确认目标卷；`du -x -k -d 1` 从数据卷和用户顶层（含隐藏项）分层排名，下钻异常大项。默认不跨外置/网络卷、不跟随链接、不遍历无关用户；权限错误单独列出。逻辑长度、分配空间和可释放空间分别表达。
- 覆盖实际存在的应用支持目录、Caches、Containers/Group Containers、Logs、Developer、隐藏工具数据、下载/媒体/项目目录；检查系统临时区、日志、更新暂存、开发资源、废纸篓、设备备份及本地快照。无法读取不等于没有；不读私人正文、凭证或会话内容。

## 最容易漏掉的残留

- **任务临时产物**：同时检查系统临时区、用户临时区、容器 `Data/tmp`、工具/项目自己的临时区，包含隐藏文件。寻找多份网站构建、测试 fixture、截图、渲染输出、热重载/增量编译文件；核对内容类型、构建配置、Git/worktree 归属和占用。源码副本、附件、发布包与 OpenCode 数据不能因目录名带 tmp 就删除。
- **Agent 资源解包与安装暂存**：从当前进程或已安装应用定位真实 App/资源包，不能假设固定 App 名称。大量随机命名隐藏文件可按日期、实占、类型与内容指纹分组；必要时与已安装包中的已知静态资源做哈希核对。仅匹配部分就只确认该部分，不能推广到旧版本或未知文件；排除当前占用和新内容。会话/归档、状态库、WAL、任务历史、录音及生成图片默认保留。
- **安装下载与升级副本**：寻找下载完成/中断的压缩包、空 payload、插件市场 staging、SDK 下载包和应用更新副本。先证明正式版本已安装且可用、下载包不再被引用或占用；staging/旧版本也可能供更新、回滚或插件运行，不凭名称整树删除。
- **项目生成物**：动态寻找 build、dist、target、测试缓存、coverage 和编译器中间文件，对照实际构建配置。与源码、发布产物、模型、node_modules/虚拟环境区分；后者通常是可用依赖，不是无用文件。清理可重建项须说明下次重新编译/下载的代价。
- **缓存与旧备份**：区分 HTTP/Code/GPU 缓存、扩展安装包、包管理器缓存、日志及手工数据库备份。录屏、草稿、TTS、离线网页/Service Worker、应用沙盒和运行时可能藏在 Cache 目录；旧备份需确认不再用于恢复。缓存清后重建，不应宣称频繁清缓存能减少 SSD 写入。

## 系统与判断限制

- 系统资产、code-sign clone、Swap、模拟器、系统更新及快照由系统管理，不直接当垃圾删除。Gradle 下载对照项目 wrapper；Docker 仅在守护进程已运行时只读查询，不启动、不 prune、不删虚拟磁盘。
- 同内容重复、文件日期老、暂未被打开都不足以单独证明无用。优先“明确一次性残留”，其次是用户愿意承担重建代价的缓存；任何未证明用途的部分独立列为待判断。
- 单次扫描只证明当前占用，文件日期和聊天历史不证明增长速度。只有用户要求跟踪时才保留少量带时间/卷标识的路径占用基线；比较同设备、同范围的系统实测数据，注明权限变化。占用增长不等于累计磁盘写入量。
